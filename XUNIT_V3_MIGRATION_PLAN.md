# xUnit v2 → v3 Migration Plan

Validated against xunit v3.2.2 source (`xunit/xunit` @ `728c1dce` + assert submodule), `Xunit.Combinatorial 2.0.24`, the current driver tree, and the official xunit.net migration guides:
- https://xunit.net/docs/getting-started/v3/migration
- https://xunit.net/docs/getting-started/v3/migration-extensibility

## Phase 1: Package & Project Structure Updates

xUnit v3 runs on Microsoft Testing Platform (MTP) and replaces VSTest. Test assemblies become **executables** with an auto-generated entry point (`XunitAutoGeneratedEntryPoint.cs`); `Microsoft.NET.Test.Sdk` and `xunit.runner.visualstudio` are no longer used. Target frameworks must be `net472`, `net8.0`, or `net10.0` (drop `netcoreapp3.1`, `net6.0` — `xunit.v3.core` ships only those TFMs).

### 1.1 `tests/BuildProps/Tests.Build.props`

| Change | From | To |
|---|---|---|
| Test framework | `xunit 2.4.2` | `xunit.v3 3.2.2` |
| Combinatorial | `Xunit.Combinatorial 1.7.31` | `Xunit.Combinatorial 2.0.24` (already targets `xunit.v3.extensibility.core`) |
| JUnit logger | `JunitXml.TestLogger 2.1.81` | `JunitXml.TestLogger 8.0.0` (MTP-compatible) |
| TFMs | `netcoreapp3.1;net6.0;net10.0;net472` | `net8.0;net10.0;net472` |

Helper / non-test projects (where `IsTestProject=false`) should reference `xunit.v3.extensibility.core` instead of `xunit.v3` (no MTP runtime). Drive this from a `Condition` on `IsTestProject` inside the props file:

```xml
<PackageReference Include="xunit.v3" Version="3.2.2" Condition="'$(IsTestProject)' != 'false'" />
<PackageReference Include="xunit.v3.extensibility.core" Version="3.2.2" Condition="'$(IsTestProject)' == 'false'" />
```

## Phase 2: TimeoutEnforcing Framework Rewrite

The v3 runner pipeline is a deeper hierarchy than v2 and uses the **singleton + protected ctor** pattern. The base classes have been verified at:
`/tmp/xunit-source/xunit-v3/src/xunit.v3.core/{Framework,Runners}/`.

### 2.0 Don't write more than necessary

xUnit v3's `XunitTestRunnerBase.RunTest` already provides per-test timeout enforcement when `IXunitTest.Timeout > 0` — `Task.WhenAny(baseTask, Task.Delay(timeout))` lives in `RunTestWithTimeout` in `XunitTestRunnerBase.cs`. The custom enforcer is only needed for what v3 doesn't do natively:

1. Apply a **default 3-minute timeout** (`XunitExtensionsConstants.DefaultTestTimeout`) when none is specified. Either set `Timeout` on the discovered `XunitTestCase` (cleanest), or override `RunTestWithTimeout` in a custom `TestRunner`.
2. **`ITestExceptionHandler` callback** when a test instance opts into post-run exception handling.
3. **`YieldNoContextAwaitable`** trick for unobserved-exception tracking (`UNOBSERVED_TASK_EXCEPTION_DEBUGGING` define).
4. **Reorder the `UnobservedExceptionTracking` test case** to run last (currently in `TimeoutEnforcingXunitTestAssemblyRunner.RunTestCollectionsAsync`).

This means we can dramatically simplify — likely 4–5 derived runner classes instead of 7+.

### 2.1 `TimeoutEnforcingXunitTestFramework : XunitTestFramework`

```csharp
public sealed class TimeoutEnforcingXunitTestFramework : XunitTestFramework
{
    public TimeoutEnforcingXunitTestFramework() { }
    public TimeoutEnforcingXunitTestFramework(string? configFileName) : base(configFileName) { }

    protected override ITestFrameworkExecutor CreateExecutor(Assembly assembly) =>
        new TimeoutEnforcingXunitTestFrameworkExecutor(
            new XunitTestAssembly(assembly, /*configFileName*/ null, assembly.GetName().Version));
}
```

- Two constructors required — `ExtensibilityPointFactory` activates with the parameterless one; the configFileName overload is required by the base contract.
- v2 `IMessageSink` ctor parameter is gone; v3 has no `DiagnosticMessageSink` field.

### 2.2 `TimeoutEnforcingXunitTestFrameworkExecutor : XunitTestFrameworkExecutor`

```csharp
internal sealed class TimeoutEnforcingXunitTestFrameworkExecutor(IXunitTestAssembly testAssembly)
    : XunitTestFrameworkExecutor(testAssembly)
{
    public override async ValueTask RunTestCases(
        IReadOnlyCollection<IXunitTestCase> testCases,
        IMessageSink executionMessageSink,
        ITestFrameworkExecutionOptions executionOptions,
        CancellationToken cancellationToken)
    {
        await TimeoutEnforcingXunitTestAssemblyRunner.Instance.Run(
            TestAssembly, testCases, executionMessageSink, executionOptions, cancellationToken);
    }
}
```

- Constructor signature: `(IXunitTestAssembly)` — no `AssemblyName`, no `ISourceInformationProvider`, no `IMessageSink`.
- `RunTestCases` returns `ValueTask` (not `void`) and now receives `CancellationToken`.

### 2.3 `TimeoutEnforcingXunitTestAssemblyRunner`

Inherit from `XunitTestAssemblyRunnerBase<…>` with the same generic args as `XunitTestAssemblyRunner`, then expose your own `Instance`. Custom logic goes in `RunTestCollections(ctxt, exception)`.

```csharp
internal sealed class TimeoutEnforcingXunitTestAssemblyRunner :
    XunitTestAssemblyRunnerBase<XunitTestAssemblyRunnerContext,
                                IXunitTestAssembly,
                                IXunitTestCollection,
                                IXunitTestCase>
{
    public static TimeoutEnforcingXunitTestAssemblyRunner Instance { get; } = new();
    private TimeoutEnforcingXunitTestAssemblyRunner() { }

    public async ValueTask<RunSummary> Run(
        IXunitTestAssembly testAssembly,
        IReadOnlyCollection<IXunitTestCase> testCases,
        IMessageSink executionMessageSink,
        ITestFrameworkExecutionOptions executionOptions,
        CancellationToken cancellationToken)
    {
        await using var ctxt = new XunitTestAssemblyRunnerContext(
            testAssembly, testCases, executionMessageSink, executionOptions, cancellationToken);
        await ctxt.InitializeAsync();
        return await Run(ctxt);
    }

    // Reorder UnobservedExceptionTracking case last (replaces v2's RunTestCollectionsAsync override).
    protected override async ValueTask<RunSummary> RunTestCollections(
        XunitTestAssemblyRunnerContext ctxt, Exception? exception) { /* ... */ }

    protected override ValueTask<RunSummary> RunTestCollection(
        XunitTestAssemblyRunnerContext ctxt,
        IXunitTestCollection testCollection,
        IReadOnlyCollection<IXunitTestCase> testCases) =>
        TimeoutEnforcingXunitTestCollectionRunner.Instance.Run(/* ... */);
}
```

Important context-class fields available in `XunitTestAssemblyRunnerBaseContext`: `TestAssembly`, `TestCases`, `MessageBus`, `Aggregator`, `CancellationTokenSource`, `AssemblyTestCollectionOrderer`, `AssemblyTestCaseOrderer`, `AssemblyFixtureMappings`. There is **no `DiagnosticMessageSink`**.

### 2.4 `TimeoutEnforcingXunitTestCollectionRunner`

```csharp
internal sealed class TimeoutEnforcingXunitTestCollectionRunner :
    XunitTestCollectionRunnerBase<XunitTestCollectionRunnerContext,
                                  IXunitTestCollection,
                                  IXunitTestClass,
                                  IXunitTestCase>
{
    public static TimeoutEnforcingXunitTestCollectionRunner Instance { get; } = new();
    private TimeoutEnforcingXunitTestCollectionRunner() { }

    public async ValueTask<RunSummary> Run(
        IXunitTestCollection testCollection,
        IReadOnlyCollection<IXunitTestCase> testCases,
        ExplicitOption explicitOption,
        IMessageBus messageBus,
        ITestCaseOrderer testCaseOrderer,
        ExceptionAggregator aggregator,
        CancellationTokenSource cancellationTokenSource,
        FixtureMappingManager assemblyFixtureMappings) { /* ctxt + Run(ctxt) */ }

    protected override ValueTask<RunSummary> RunTestClass(
        XunitTestCollectionRunnerContext ctxt,
        IXunitTestClass? testClass,
        IReadOnlyCollection<IXunitTestCase> testCases) =>
        TimeoutEnforcingXunitTestClassRunner.Instance.Run(testClass!, testCases,

```

- v2's `IReflectionTypeInfo @class` parameter is gone. `IXunitTestClass` carries the class info directly.

### 2.5 `TimeoutEnforcingXunitTestClassRunner`

Override `RunTestMethod(ctxt, testMethod, testCases, constructorArguments)`; forward to `TimeoutEnforcingXunitTestMethodRunner.Instance.Run(...)`.

### 2.6 `TimeoutEnforcingXunitTestMethodRunner`

Two interesting properties of v3:
- `XunitTestMethodRunnerBase.RunTestCase` already handles both fact and theory cases uniformly via `IXunitTestCase.CreateTests()` and `XunitTestCaseRunner.Instance.Run(...)`. We no longer distinguish `XunitTheoryTestCase` — **DELETE `TimeoutEnforcingXunitTheoryTestCaseRunner`**.
- `SkippableTestMessageBus` is no longer needed — v3 detects the `$XunitDynamicSkip$` prefix natively in `XunitTestRunnerBase`. **DELETE**.

Override `RunTestCase` only if you need to inject the timeout default; otherwise this class can be skipped entirely (use `XunitTestMethodRunner.Instance` directly from the class runner).

### 2.7 `TimeoutEnforcingXunitTestCaseRunner`

Override `RunTest(ctxt, test)` and forward to `TimeoutEnforcingTestRunner.Instance.Run(...)`.

- v2's `CreateTestRunner(...)` factory is gone — there is no `ITestRunner` factory in v3. You override `RunTest` directly.

### 2.8 ~~`TimeoutEnforcingXunitTheoryTestCaseRunner`~~ — DELETE

v3 has no separate `XunitTheoryTestCaseRunner`. Delay-enumerated theories use `XunitDelayEnumeratedTheoryTestCase` and feed back through the same `XunitTestCaseRunner`.

### 2.9 `TimeoutEnforcingTestRunner`

This is where the per-test timeout default goes (if not pre-applied at discovery time):

```csharp
internal sealed class TimeoutEnforcingTestRunner : XunitTestRunnerBase<XunitTestRunnerContext, IXunitTest>
{
    public static TimeoutEnforcingTestRunner Instance { get; } = new();
    private TimeoutEnforcingTestRunner() { }

    public async ValueTask<RunSummary> Run(/* same params as XunitTestRunner.Run */) { /* ctxt + Run(ctxt) */ }

    protected override async ValueTask<TimeSpan> InvokeTest(
        XunitTestRunnerContext ctxt, object? testClassInstance)
    {
        // Apply DefaultTestTimeout when ctxt.Test.Timeout == 0.
        // Dispatch ITestExceptionHandler.HandleException(...) via testClassInstance.
        // Wrap base.InvokeTest(ctxt, testClassInstance) with YieldNoContextAwaitable
        //   + Task.WhenAny(baseTask, Task.Delay(timeout)) when needed.
    }
}
```

- v2 override target was `InvokeTestMethodAsync(ExceptionAggregator)` returning `Task<decimal>`. v3 override is `InvokeTest(ctxt, testClassInstance)` returning `ValueTask<TimeSpan>`.
- `PreInvoke(ctxt)` / `PostInvoke(ctxt)` are also available; default impls call before/after attribute hooks.

### 2.10 ~~`TimeoutEnforcingTestInvoker`~~ — DELETE as a separate class

There is no standalone `XunitTestInvoker` in v3. Move the timeout/exception-handler/yield logic into `TimeoutEnforcingTestRunner.InvokeTest`.

### 2.11 ~~`SkippableTestMessageBus`~~ — DELETE

v3 detects `$XunitDynamicSkip$` natively. The plan claim that "`SkipException` still exists" is true (it's still in `Xunit.Sdk`), but its constructor is now **non-public** — only `SkipException.ForSkip(message)` is callable, which prepends the dynamic-skip token. See Phase 3.

### 2.12 KEEP / MOVE: `ITestExceptionHandler`

Trivial interface (`HandleException(Exception)`); keep as-is or move out of the `TimeoutEnforcing` folder if you want.

## Phase 3: SkipException → `Assert.Skip*`

**Correction to original plan**: `throw new SkipException(message)` does **not** compile against `xunit.v3.assert 3.2.2`. The constructor is non-public; only the static factory `SkipException.ForSkip(message)` is callable, and it prepends `DynamicSkipToken.Value` (`"$XunitDynamicSkip$"`) to the message. The runtime's dynamic-skip detection requires that prefix.

Migration is mandatory.

| v2 | v3 |
|---|---|
| `throw new SkipException(reason)` | `Assert.Skip(reason)` (`[DoesNotReturn]`) |
| `if (!cond) throw new SkipException(reason)` | `Assert.SkipUnless(cond, reason)` |
| `if (cond) throw new SkipException(reason)` | `Assert.SkipWhen(cond, reason)` |

Currently 50 `throw new SkipException(...)` sites across 18 files (verified via `git grep`). The fluent helpers (`RequireServer`, `RequireEnvironment`, `RequireProcess`, `RequirePlatform`) `return this` for chaining; `Assert.Skip` is `[DoesNotReturn]`, so an inline `Assert.SkipWhen(condition, reason)` works without breaking the chain.

## Phase 4: Test Case Discovery Rewrite

The discoverer interface changes shape:

```csharp
// v2
IEnumerable<IXunitTestCase> Discover(
    ITestFrameworkDiscoveryOptions discoveryOptions,
    ITestMethod testMethod,
    IAttributeInfo factAttribute);

// v3
ValueTask<IReadOnlyCollection<IXunitTestCase>> Discover(
    ITestFrameworkDiscoveryOptions discoveryOptions,
    IXunitTestMethod testMethod,
    IFactAttribute factAttribute);
```

Registration: `[XunitTestCaseDiscoverer("TypeName", "Assembly")]` → `[XunitTestCaseDiscoverer(typeof(MyDiscoverer))]`.

Use `TestIntrospectionHelper.GetTestCaseDetails(discoveryOptions, testMethod, factAttribute)` to populate display name / unique id / source info, then construct the test case. Pattern from `FactDiscoverer`:

```csharp
var details = TestIntrospectionHelper.GetTestCaseDetails(discoveryOptions, testMethod, factAttribute);
return new XunitTestCase(
    details.ResolvedTestMethod,
    details.TestCaseDisplayName,
    details.UniqueID,
    details.Explicit,
    details.SkipExceptions,
    details.SkipReason,
    details.SkipType,
    details.SkipUnless,
    details.SkipWhen,
    testMethod.Traits.ToReadWrite(StringComparer.OrdinalIgnoreCase),
    sourceFilePath: details.SourceFilePath,
    sourceLineNumber: details.SourceLineNumber,
    timeout: details.Timeout);
```

### 4.1 `UnobservedExceptionTestDiscoverer`

- New ctor parameters: discoverers no longer take `IMessageSink` — they have a parameterless ctor.
- After creating the `XunitTestCase`, mutate `Traits` to add the `"Category" → "UnobservedExceptionTracking"` entry. Note `Traits` value type changed: `HashSet<string>` (not `List<string>`).
- Return `new ValueTask<IReadOnlyCollection<IXunitTestCase>>([testCase])`.

### 4.2 `UnifiedTestsDiscoverer`

- Drop `IMessageSink _messageSink` field — no longer available.
- Replace `factAttribute.GetNamedArgument<string>(...)` with a direct cast: `var attr = (UnifiedTestsTheoryAttribute)factAttribute;` then read `attr.Path`, `attr.SkippedTestsProvider`, `attr.SkippedFilesProvider`.
- Replace `testMethod.TestClass.Class as ReflectionTypeInfo` and `.Type` with `IXunitTestMethod.TestClass.Class` (a `Type` directly).
- Replace v2 `XunitTestCase(messageSink, TestMethodDisplay, TestMethodDisplayOptions, testMethod, [args])` ctor + `testCase.SourceInformation = new SourceInformation { FileName, LineNumber }` with the v3 ctor that takes `sourceFilePath` / `sourceLineNumber` directly.

`UnifiedTestsTheoryAttribute(string path) : FactAttribute` works as-is — `FactAttribute` in v3 still takes `[CallerFilePath]` / `[CallerLineNumber]` defaults but those compose without changes here. Update the discoverer registration attribute to `[XunitTestCaseDiscoverer(typeof(UnifiedTestsDiscoverer))]`.

## Phase 7.5: Other v2→v3 Breaking Changes (audit results)

The official migration guide flags several behavior/API changes that don't fit cleanly into the framework-rewrite phases. Audited results for this tree:

- **`async void` test methods → `async Task`** (mandatory; v3 fast-fails them at runtime). Two sites confirmed:
  - `tests/MongoDB.Driver.Tests/PinnedShardRouterTests.cs:60` — `Test_Unpin_For_Next_Transaction`
  - `tests/MongoDB.Driver.Tests/PinnedShardRouterTests.cs:120` — `Test_Unpin_For_Non_Transaction_Operation`

  (A third hit in `TimeoutEnforcingXunitTestFrameworkExecutor.RunTestCases` is an override of the v2 base API and disappears with the Phase 2 rewrite.)

- **`Record.ExceptionAsync` now returns `ValueTask`** and accepts `ValueTask`-returning lambdas. 177 call sites in the tree, almost all of them `await Record.ExceptionAsync(() => …)` patterns that compile unchanged because `await` is duck-typed across `Task`/`ValueTask`. Watch for any code that assigns the return value to a `Task<Exception>` variable or passes it where `Task` is required — those need an explicit `.AsTask()`.

- **`IAsyncLifetime` semantics changed** (now derives from `IAsyncDisposable`; only `DisposeAsync` is invoked even if the type also implements `IDisposable`). No effect on this tree — `IAsyncLifetime` is not implemented anywhere. `IClassFixture<T>` / `ICollectionFixture<T>` usages (a handful: `RegisterObjectSerializerCollection`, `IntegrationTest<TFixture>`) continue to work without changes.

- **No custom `DataAttribute` / `MemberDataAttributeBase` subclasses, no `BeforeAfterTestAttribute` subclasses, no `IFrontController` / `IRunnerReporter` extensibility code in the tree.** All those v3 API breaks are no-ops here.

- **`xunit.analyzers`** is mentioned only inside `<NoWarn>` comments — not referenced as a package. The official guide says the package itself is unchanged across v2/v3, so nothing to do.

- **`xunit.runner.visualstudio` 3.x compat mode** is the official guide's recommended path. This plan instead removes it (and `Microsoft.NET.Test.Sdk`) and goes pure MTP via `<OutputType>Exe</OutputType>`. The two are incompatible — pick one. Pure MTP is cleaner for CI and avoids carrying VSTest forward; the trade-off is that VS Test Explorer needs a recent version that supports MTP discovery (Rider 2024.1+, VS 17.10+, `dotnet test` on 8.0.300 SDK or newer).

- **`JunitXml.TestLogger 8.0.0`** must be the MTP-compatible build, not a VSTest logger. Verify the v8 line targets MTP before committing to it; if not, fall back to xunit's built-in `-junit` reporter or switch to one of the maintained MTP loggers.

## Phase 8: Build, Run, and Validate

1. Apply Phase 1 package/csproj changes; run `dotnet restore` and `dotnet build` per project; let compile errors guide the rewrite of TimeoutEnforcing (Phase 2) and the discoverers (Phase 4).
2. Sweep `Xunit.Abstractions` usings (Phase 7) and `throw new SkipException` sites (Phase 3) — both produce compile errors that pinpoint the work.
3. Smoke-test: `dotnet test tests/MongoDB.Bson.Tests` (now MTP-driven) confirms the framework, traits, dynamic skip, and combinatorial paths work end-to-end. Then expand to `MongoDB.Driver.Tests` and verify timeouts trip via `[Fact(Timeout = …)]` and the default-3-min path.
4. Verify the unobserved-exception tracking test still runs last and reports any captured exceptions.
5. Verify `JunitXml` output is generated under MTP — flag layout differs from VSTest.

## Risk Notes

- **MTP runner integration**: VS Test Explorer / Rider / `dotnet test` need recent versions to discover MTP test executables. Confirm CI agents do too.
- **Astrolabe Exe-on-Exe**: `MongoDB.Driver.Tests` becoming `OutputType=Exe` may collide with `AstrolabeWorkloadExecutor`'s own entry point. If `dotnet build` fails with "duplicate Main", set `<GenerateProgramFile>false</GenerateProgramFile>` in Astrolabe or extract shared code.
- **Default 3-minute timeout**: setting it in the discoverer (`Timeout = (int)DefaultTestTimeout.TotalMilliseconds` when factAttribute.Timeout == 0) is simpler than overriding `RunTest`, and means individual `[Fact(Timeout = …)]` attributes still win.
- **`ExceptionAggregator` is now a struct** — copy-by-value semantics. Use `.Clone()` when forwarding to a child runner so the child can't mutate the caller's aggregator.
